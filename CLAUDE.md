# Reporting App — CLAUDE.md

## What This App Does

A locally-run web UI that continuously collects input (files, emails, free text) with automatic date-stamping, deduplicates it, and generates reports on demand:

- **Weekly report**: Markdown file (`.md`)
- **Monthly report**: Follows a user-provided template (content and structure)

Reports are never auto-generated. The user initiates them explicitly.

## Data Model

Every collected item is an **Entry**:

| Field        | Type       | Notes                                      |
|--------------|------------|--------------------------------------------|
| `id`         | UUID       | Primary key                                |
| `type`       | enum       | `file`, `email`, `text`                    |
| `content`    | text       | Extracted text or body                     |
| `source`     | str        | Filename, sender address, or "manual"      |
| `date_stamp` | datetime   | Auto-assigned at ingestion (UTC)           |
| `hash`       | str        | SHA-256 of normalized content (for dedup)  |
| `tags`       | list[str]  | Optional user-supplied tags                |

---

## Input Collection

### File upload
- Accept common formats: `.txt`, `.pdf`, `.docx`, `.eml`, `.csv`, `.md`
- Extract text content at upload time and store in `content`
- Store raw file under `data/uploads/`

### Email
- Paste email body directly into the UI **or** upload an `.eml` file
- Parse subject, sender, body; store as a single Entry with `type=email`

### Free text
- Textarea in the UI; user types or pastes any note
- `source` is set to `"manual"`

### Date stamping
- All entries receive `date_stamp = utcnow()` at ingestion
- Users may optionally override the date if the content predates today

---

## Deduplication

Dedup runs at **ingestion time** (not at report time):

1. Normalize content: lowercase, collapse whitespace, strip punctuation
2. Compute SHA-256 hash of normalized content
3. If hash already exists in the database, reject the entry and notify the user
4. Near-duplicate detection (optional, Phase 2): cosine similarity > 0.95 on TF-IDF vectors flags a warning but does not hard-reject

## Report Generation

Reports are triggered by the user via a button in the UI or an API call. They are never scheduled automatically.

### Weekly Report (`/reports/weekly/`)

- Covers the 7 days ending at the moment of generation (or a user-specified date range)
- Output: a single `.md` file saved to `reports/`
- Structure:

```markdown
# Weekly Report — YYYY-Www (Mon DD – Mon DD)

## Summary
<auto-generated 2–4 sentence narrative>

## Entries by Type

### Files
- <date> — <source>: <first 200 chars of content>

### Emails
- <date> — <source>: <subject> — <first 200 chars of body>

### Notes
- <date>: <content>

## Key Themes
<bullet list extracted from content>
```

### Monthly Report (`/reports/monthly/`)

- Covers the calendar month selected by the user
- Output format and structure are **entirely defined by the user-provided template** in `templates/monthly_report_template.*`
- The template uses placeholder tokens (e.g. `{{entries}}`, `{{summary}}`, `{{month}}`) that the generator replaces with real content
- If no template is found, generation is blocked and the user is prompted to upload one
- Supported template formats: `.docx`, `.md`, `.html`

## API Endpoints (FastAPI)

| Method | Path                        | Description                            |
|--------|-----------------------------|----------------------------------------|
| POST   | `/entries`                  | Submit text entry                      |
| POST   | `/entries/upload`           | Upload a file or .eml                  |
| GET    | `/entries`                  | List entries (filterable by date/type) |
| DELETE | `/entries/{id}`             | Delete an entry                        |
| POST   | `/reports/weekly`           | Generate weekly report                 |
| POST   | `/reports/monthly`          | Generate monthly report                |
| GET    | `/reports`                  | List generated reports                 |
| GET    | `/reports/{filename}`       | Download a generated report            |
| POST   | `/templates/monthly`        | Upload/replace monthly template        |
| GET    | `/templates/monthly`        | Download current monthly template      |

## Tech Stack

| Layer     | Choice              | Reason                                              |
|-----------|---------------------|-----------------------------------------------------|
| Backend   | Python + FastAPI    | Async, fast to develop, easy file/text handling     |
| Database  | SQLite              | Zero-config, local, sufficient for daily volumes    |
| ORM       | SQLAlchemy (sync)   | Simple CRUD, no migration complexity needed early on|
| Frontend  | Vanilla JS + HTML   | No build step, runs in any browser locally          |
| PDF parse | `pdfplumber`        | Reliable text extraction                            |
| DOCX      | `python-docx`       | Read and write Word documents                       |
| Dedup     | hashlib (SHA-256)   | Fast, deterministic, no dependencies                |

## Key Constraints and Decisions

- **No cloud, no auth**: This is a local-only tool. No login, no remote storage, no external APIs required.
- **Reports on demand only**: No cron jobs, no watchers. The user clicks to generate.
- **Template is sacred**: The monthly report generator must not alter the template's layout, fonts, or structure — only fill in the placeholders.
- **Dedup is hard at ingestion**: Once rejected as a duplicate, an entry is never stored. The user sees an immediate rejection notice.
- **One SQLite file**: Keep everything in `data/entries.db`. Do not split into multiple databases.
- **Reports are immutable snapshots**: Generated files are never overwritten. Each generation appends a timestamp to the filename (e.g. `weekly_2026-W21_generated-20260526T1430.md`).

## Out of Scope (for now)

- Email server integration (IMAP/SMTP polling) — user pastes or uploads manually
- Multi-user support
- Cloud sync or backup
- Scheduled/automatic report generation
- AI summarization (the summary sections are placeholder text until this is explicitly added)
